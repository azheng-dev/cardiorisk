# Data layer

How datasets are fetched, where they live, and the rules that keep this public repo PII-free.

## Cardinal rule

**No real patient data and no copyrighted PDF corpora are committed to this repository, ever.** The only tabular file in version control is the synthetic test fixture at [`backend/tests/fixtures/hfp_mini.csv`](../../backend/tests/fixtures/), generated by a deterministic seeded PRNG and documented as such in its accompanying [`README.md`](../../backend/tests/fixtures/README.md). The Phase 3.1 corpus PDFs (RACGP + NVDPA) are fetched at build time and never redistributed by the repo.

This rule is enforced by:

1. The `data/raw/`, `data/interim/`, `data/external/`, and `data/processed/` directories being gitignored except for `.gitkeep` markers.
2. The global `*.pdf` rule in `.gitignore` (with `!docs/**/*.pdf` as the only allow).
3. The [`scripts/no_raw_data.sh`](../../scripts/no_raw_data.sh) pre-commit hook, which refuses to add any `*.csv` / `*.tsv` / `*.parquet` / `*.feather` outside `tests/fixtures/`, **or any `*.pdf` outside `docs/`**.
4. The `secret-scan` (gitleaks) CI job, which runs on every push and PR.

If you ever need to circumvent these for a legitimate reason, the answer is to put the file under `data/raw/` or `data/external/` (both gitignored) and add a checksum in `data/checksums/`. Don't loosen the gates.

## Directory layout

```
data/
├── checksums/        # SHA-256 lockfiles for every fetched source. Committed.
├── external/         # Reference data that doesn't fit raw/processed (rare).
├── interim/          # Intermediate artefacts; a script's output that another reads.
├── processed/        # Combined / cleaned tables ready for modelling.
└── raw/              # Untouched source files as fetched. Gitignored except .gitkeep.
```

Only `data/checksums/` and the `.gitkeep` markers are version-controlled. Everything else regenerates from the fetch + build scripts.

## Datasets

### Heart Failure Prediction (HFP), via UCI Heart Disease subsets

Used by Phase 2.1 onward. The combined HFP-schema parquet in `data/processed/combined.parquet` is built from four UCI subsets (we don't pull the Kaggle [HFP combined CSV](https://www.kaggle.com/datasets/fedesoriano/heart-failure-prediction) by default; it omits the source column we need for LODO-CV).

| Source | UCI URL | Pinned in |
|---|---|---|
| Cleveland | `archive.ics.uci.edu/ml/.../processed.cleveland.data` | [`uci_cleveland.sha256`](../../data/checksums/uci_cleveland.sha256) |
| Hungarian | `archive.ics.uci.edu/ml/.../processed.hungarian.data` | [`uci_hungarian.sha256`](../../data/checksums/uci_hungarian.sha256) |
| Switzerland | `archive.ics.uci.edu/ml/.../processed.switzerland.data` | [`uci_switzerland.sha256`](../../data/checksums/uci_switzerland.sha256) |
| Long Beach VA | `archive.ics.uci.edu/ml/.../processed.va.data` | [`uci_va.sha256`](../../data/checksums/uci_va.sha256) |

The schema mapping (UCI 14-column → HFP 11+1) and the rationale for using UCI directly over the Kaggle combined CSV are in [`docs/research/04-revised-design.md §3`](../research/04-revised-design.md) and the [combine module docstring](../../backend/cardiorisk/data/combine.py).

## Fetching

From the repo root:

```bash
# 1. Download the four UCI subsets into data/raw/, verify against pinned SHA-256.
#    No credentials needed.
uv run --project backend python backend/scripts/fetch_hfp.py

# 2. Combine into data/processed/combined.parquet with a `source` column.
uv run --project backend python backend/scripts/build_combined.py

# 3. (Optional) Cross-check against the Kaggle-published HFP combined CSV.
#    Requires KAGGLE_USERNAME + KAGGLE_KEY in env (https://www.kaggle.com/settings).
uv run --project backend python backend/scripts/fetch_hfp.py --include-kaggle
```

CI runs the same scripts in `--use-fixture` mode against the synthetic fixture, with no network and no credentials, so the data layer is exercised end-to-end on every PR. See [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml).

### What `fetch_hfp.py` does

For each UCI source:

1. If the file exists in `data/raw/` and its SHA-256 matches the pinned `data/checksums/uci_<source>.sha256` → log `[reused]`, do nothing.
2. Otherwise: stream-download with a 60-second timeout, write atomically (`.part` then rename), compute SHA-256.
   - If no checksum is pinned yet → write a new lockfile (first-run case for a maintainer).
   - If the observed digest doesn't match the pin → raise `FetchError` and abort. This is how upstream drift is detected.

Re-runs are a no-op when checksums match. Pass `--force` to bypass the cache.

### What `build_combined.py` does

Reads the four UCI files, applies the schema mapping in [`cardiorisk.data.combine.map_uci_to_hfp`](../../backend/cardiorisk/data/combine.py), concatenates them into one DataFrame with a `source` column, and writes parquet to `data/processed/combined.parquet`. The `source` column is the LODO-CV grouping variable; it is **not** a feature.

In `--use-fixture` mode, it loads `backend/tests/fixtures/hfp_mini.csv` directly (already in HFP schema), tags `source = 'fixture'`, and writes the same parquet path. CI uses this mode.

## Verifying a fetched file by hand

```bash
sha256sum data/raw/processed.cleveland.data
cat data/checksums/uci_cleveland.sha256
# Both digests should match.
```

If they diverge, either the upstream changed (verify with the original URL, then update the lockfile and document why in the PR) or the file was corrupted in transit (re-fetch with `--force`).

## What lives in `data/checksums/`

Plain-text lockfiles, one per fetched source, with the format:

```
<64-hex-char-sha256>  # source: <upstream URL>
```

Example: [`data/checksums/uci_cleveland.sha256`](../../data/checksums/uci_cleveland.sha256). Committed to the repo so any cloner can verify their downloads exactly match what the maintainer worked from.

## What lives in `backend/tests/fixtures/`

The synthetic HFP-schema fixture used by CI to exercise the data + EDA stack without network. **No real patient records.** Generator: [`backend/scripts/generate_fixture.py`](../../backend/scripts/generate_fixture.py); seed locked at `20260505` so the fixture is byte-for-byte deterministic. Full description: [`backend/tests/fixtures/README.md`](../../backend/tests/fixtures/README.md).

### Phase 3.1 — RACGP + NVDPA guideline corpus

Used by the Phase 3 RAG layer. Source PDFs live under `data/external/corpus/raw/` (gitignored); per-page parsed JSONLs and per-strategy chunk JSONLs land under `data/external/corpus/{parsed,chunks}/` and `data/external/corpus/manifest.json` (also gitignored — derived from the raw bytes). Checksums are pinned in `data/checksums/corpus_*.sha256`.

| Source | Publisher | Pinned in |
|---|---|---|
| RACGP Red Book — CVD prevention chapter | RACGP | [`corpus_racgp_redbook_cvd.sha256`](../../data/checksums/corpus_racgp_redbook_cvd.sha256) (written on first fetch) |
| Australian Guideline for assessing and managing CVD risk (2023, full document) | NVDPA | `corpus_nvdpa_2023_full_guideline.sha256` (written on first fetch) |
| Australian CVD Risk Assessment 2023 — Quick reference guide | NVDPA | `corpus_nvdpa_2023_quick_reference.sha256` (written on first fetch) |

The complete source list lives in [`backend/cardiorisk/rag/ingest/sources.py`](../../backend/cardiorisk/rag/ingest/sources.py). The decision rationale (parser choice, chunking strategy, manifest contract, eval-set location) is documented in [ADR-015](../adr/015-corpus-ingestion.md) and [docs/research/12-corpus-ingestion-design.md](../research/12-corpus-ingestion-design.md).

#### Fetching + building

```bash
# 1. Download the 3 corpus PDFs into data/external/corpus/raw/, verify against
#    pinned SHA-256. First run for a maintainer writes the lockfiles.
uv run --project backend python backend/scripts/fetch_corpus.py

# 2. Parse + chunk (3 pluggable strategies) + write manifest.json.
uv run --project backend python backend/scripts/build_corpus.py

# 3. Re-build with one strategy (faster; useful when iterating in Phase 3.2).
uv run --project backend python backend/scripts/build_corpus.py --strategy token
```

CI runs both scripts in `--use-fixture` mode against the markdown fixture under [`backend/tests/fixtures/corpus_mini/`](../../backend/tests/fixtures/corpus_mini/), with no network and no PDFs, so the ingest layer is exercised end-to-end on every PR. Phase 3.2's retrieval eval (50-Q expansion + chunking A/B + embeddings choice) reads the manifest produced by `build_corpus.py`.
